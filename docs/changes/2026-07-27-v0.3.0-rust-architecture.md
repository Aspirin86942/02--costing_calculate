## 实际结果

- 保留 `costing-cli`、`costing-core`、`costing-xlsx`、`costing-oracle-tests` 四个 crate。
- `costing-cli` 继续通过 `application::execute(RunRequest) -> RunOutcome` 提供稳定应用接口。
- `costing-core` 新增单一内存处理入口 `process_workbook`，内部完成标准化、拆分、事实表、异常分析、质量指标和展示模型构建。
- normalize、split、fact、anomaly、presentation 等实现模块改为 crate 内部可见，CLI 不再逐个编排内部步骤。
- 路径与输入输出验证从 `run.rs` 移入独立模块；Manifest、运行、事实表、异常和 writer 的大型内联测试拆到相邻测试文件。
- 标准 writer 与 low-memory writer 仍由 `costing-xlsx` 内部统一选择，没有新增生产依赖、crate 或无业务价值的抽象层。
- 架构测试新增 CLI 不得调用 core 内部步骤、core 内部模块不得公开的约束。
