# GB/SK 命令行提速实验

完整 SK 的一次审计运行从 42.38 秒降至 18.61 秒，该次输出通过逐成员比对。下列数据来自以 `718644236fff4d9f4a92a03295023d323f3023cc` 为基线的 Linux x86-64 候选实验。此后 0.3.1 采用了五项实现，完整 SK 的稳定性能验收仍受原版程序崩溃和输出差异影响。[实验源码补丁](../performance/candidates/2026-11-20-sk-speed.patch)和[0.3.1 版本说明](releases/v0.3.1.md)

| 真实输入 | 原版审计耗时 | 最终候选审计耗时 | 原版输出字节 | 最终候选输出字节 |
| --- | ---: | ---: | ---: | ---: |
| GB | 2.123 秒 | 1.558 秒 | 3,808,076 | 3,808,076 |
| 完整 SK | 42.381 秒 | 18.607 秒 | 75,430,019 | 75,372,873 |

表中耗时来自功能比对时各一次运行的 Manifest（审计记录），当时还有其他本地验证任务运行。完整 SK 的读取从 21.79 秒降至 6.96 秒，导出从 14.82 秒降至 8.64 秒。

## 候选实现

| 改动 | 实现 |
| --- | --- |
| 并行读取 | 大型单工作表 XLSX 按完整 XML 行分块。每块复用 Calamine 和原工作簿的样式、共享字符串及表头，再按原顺序拼回。不能独立解析的分块交回原读取器。 |
| 内存分配 | 命令行程序使用 `mimalloc 0.1.52` 分配和回收内存。 |
| 后台压缩 | 低内存写出时，后台线程将行压缩到输出目录内的临时文件。保存时核对表头和 ZIP 选项，必要时从原始行文件重新生成。 |
| 文本共享 | 将已有的 `Arc<str>` 传给写出库，每个单元格沿用同一份文本及原格式检查。 |
| 命令行退出 | 成功写出后由操作系统在进程退出时回收展示表。公开的 `application::execute` 继续逐次释放内存，临时文件按原流程关闭和清理。 |

## 正确性

真实 GB 和 163,340,340 字节的完整 SK 各验证了日常模式和审计模式，共四次跨版本比较。三张表、业务摘要以及工作簿内所有受契约约束的 ZIP 成员均一致。审计模式另核对输入、输出的 SHA-256 和低内存标记。

27 个合成场景覆盖 GB/SK、58 列完整 SK、月份筛选、空结果、只检查模式、两个数据种子，以及低内存阈值两侧。全部通过。虚构数据和真实数据均使用原容差。候选通过 222 项 Rust 测试和 487 项 Python 测试，Linux 跳过 1 项 Windows 专用检查。

Windows MSVC 目标的 Excel 读写模块通过编译检查。完整 Windows 命令行程序在构建分配器时缺少 Windows C 运行库头文件 `wchar.h`。Windows 原生运行、内存和发布包验收尚待验证。

## 八对交错测量

每项均与同一冻结源码基线独立比较，每对交换运行顺序，计时结束后核验工作簿。耗时改善率取逐对改善率的中位数，内存变化按两侧峰值驻留内存中位数计算。除后台压缩使用超过低内存阈值的 SK 样本，其余使用完整格式的中型 SK 合成样本。

| 单项及实现 | 原版耗时中位数 | 候选耗时中位数 | 耗时改善 | 峰值内存变化 | 胜出 | 主场景结果 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 共享写出文本，最终源码 | 2.736 秒 | 2.553 秒 | 6.22% | −5.67% | 8/8 | 通过本地主场景 |
| 后台压缩，压缩结果暂存内存的原型 | 10.410 秒 | 8.993 秒 | 13.61% | +2.90% | 8/8 | 通过本地主场景，最终版本改为落盘 |
| 并行读取原型 | 2.698 秒 | 2.210 秒 | 17.97% | +26.52% | 8/8 | 内存和阶段回退超限 |
| 并行读取，最终源码 | 2.714 秒 | 2.625 秒 | 3.08% | +25.35% | 8/8 | 耗时低于 5% 门槛，内存和写出填充回退超限 |
| 分配器，首次独立构建 | 2.651 秒 | 2.132 秒 | 20.12% | +27.47% | 8/8 | 超过 5% 内存上限 |
| 退出回收原型 | 2.662 秒 | 2.605 秒 | 2.79% | +0.02% | 8/8 | 低于 5% 耗时门槛 |

最终分配器复测取得 5 对后，候选进程崩溃。最终退出回收复测与落盘压缩的校准均在原版进程崩溃后停止。共享文本的独立可执行文件在两次构建中哈希相同，扩展验收所需的另外一次干净构建遇到 Rust 编译器内部错误，使用独立构建目录和两个编译任务重试时编译器也发生了段错误。

## 真实输入的验收状态

完整 SK 的最终六核校准在原版预热时收到 `SIGABRT`。另外登记的双核诊断使用相同输入和程序，原版生成的总表有数值单元格超过既定 `1e-9` 容差，逐次核验随即停止。真实 GB 的日常模式原版预热收到 `SIGSEGV`，审计模式的原版自比还出现了共享字符串及三张工作表的差异。七个已登记可执行文件的 SHA-256 复核均通过。

在保留的两份原版完整 SK 输出中，逐行检查总表的 812,589 行，发现三处数值超差，另有一行的工作表 XML 出现损坏。原版 GB 两次输出中也有四处数值超差。这些结果限制了本机对正式版稳定性能的判定。

完整 SK 五项组合缺少有效的八对耗时和独立五次复测，收益和内存尚未达到可采纳的证据要求。原始报告、失败输出和源文件哈希位于本机忽略目录 `.pytest-tmp/optimization/20261120-speed/` 和 `.pytest-tmp/optimization/20261120-speed-final/`。前者保存原型数据，后者保存交付程序的真实比对、合成保护、正式测量和双核诊断。
