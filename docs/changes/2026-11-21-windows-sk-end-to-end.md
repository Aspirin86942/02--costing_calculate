# Windows SK 端到端耗时复测

2026-11-21 在同一台 Windows x64 机器上，使用两份真实 SK 输入重测。对照程序为冻结的 `e1c8d2a`。当前常规版和 PGO 版来自提交 `0d80c72` 的两个 Windows ZIP，解包后核对了压缩包、可执行文件和输入的 SHA-256。三版均用内嵌配置，以普通模式读取输入、完成成本计算和异常分析、写出三张工作表。计时从启动 CLI 到进程退出。

## 相对冻结版的改善

每个输入先做 4 对同程序校准，均在首次通过。每种当前构建分别与冻结版做 8 对，双方先预热，奇偶轮交替先后顺序。耗时降幅取每对 `(旧耗时 − 新耗时) / 旧耗时` 的中位数。每份节省时间也逐对计算。独立五次与八对测量来自不同批次。

| 输入 | 比较版本 | 八对冻结版中位数 | 八对当前版中位数 | 每份节省 | 耗时降幅 | 当前版胜出 |

## 正确性与测量口径

两份输入各生成并核验了 61 份工作簿，覆盖预热、校准、配对及独立五次。每份输出的受约束 ZIP 成员均与对应版本已验收的工作簿匹配，核对了各成员的压缩数据 SHA-256、CRC、长度和压缩方法。核心属性中的时间戳按比较器口径排除。配对程序的业务行数、问题分类与计数一致，当前两版输出的工作表 ZIP 描述符检查全部通过。

当前两版在两份输入上都通过耗时、峰值工作集和文件大小门禁。冻结版完整 SK 的独立五次均成功写出，其最大文件为 75,372,863 字节，超过现行 48,658,823 字节上限。当前两版的完整 SK 最大均为 32,003,666 字节。本次计时使用普通写出，未请求 Manifest。[Windows 配对脚本](../../tools/validation/measure_paired_release.ps1) · [独立五次脚本](../../tools/validation/measure_release.ps1)
