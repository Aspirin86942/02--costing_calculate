# Costing Calculate v0.2.0

This release completes the production-readiness scope defined for v0.2.0:
reproducible CI and builds, a stable Rust application boundary, governed
configuration, auditable manifests, atomic publication, verified Windows
packaging, and two controlled performance experiments.

## Compatibility

- Rust remains the only production entry point. Python remains available only
  as the migration oracle and regression implementation.
- The frozen GB/SK business rules, Decimal semantics, three-Sheet workbook,
  quality metrics, error-log behavior, console JSON, and exit codes remain
  compatible with the v0.1 baseline.
- External configuration can change only the reviewed product list/order and
  safe input pattern. Independent cost items, anomaly rules, workbook
  contracts, and writer parameters remain sealed.
- Existing output workbooks and Manifest files are never overwritten.

## Main changes

- Pinned Windows and Ubuntu CI covers Rust, Python, contracts, architecture,
  synthetic end-to-end behavior, and protected baseline governance.
- `RunRequest`, `RunOutcome`, and `execute` form a typed application boundary;
  the CLI shell is limited to argument parsing, rendering, and exit mapping.
- `--version-json` reports the source commit, exact Rust toolchain, target,
  schema versions, and deterministic commit-derived build timestamp.
- Versioned TOML configuration has strict parsing, a closed JSON schema,
  semantic SHA-256, source provenance, and sealed-field enforcement.
- Optional `RunManifestV1` success/failure records include immutable input and
  output identities, effective configuration, quality metrics, counts, stage
  timings, and optional path redaction.
- Workbooks and manifests use same-directory temporary files, flush/sync, and
  no-overwrite atomic publication.
- The Windows x86_64 ZIP is self-contained and carries default configuration,
  schemas, examples, internal checksums, and an external ZIP checksum.

## Performance decisions

- Adopted borrowed text access only in comparison hot paths. The controlled SK
  experiment reduced normalize median time by `22.1178%` and full-run wall
  median by `1.1771%`, with zero contract or oracle mismatch.
- Retained ZIP compression Level 5. Levels 3 and 2 improved full-run wall and
  save time, but exceeded the frozen SK output-size limit by `3,869,470` and
  `8,286,515` bytes respectively, so both were rejected.
- No performance threshold or contract baseline was relaxed.

## Verification

The final source is accepted only after:

- Rust format, Clippy, workspace/all-targets/all-features tests;
- Python fast regression, Ruff check, and Ruff format;
- full real-data GB/SK Python-versus-Rust workbook and runtime oracle;
- standard and low-memory atomicity/failure-injection coverage;
- SK paired performance/PWS/output-size gates and GB regression;
- isolated Windows package smoke with Rust and Python removed from the child
  environment, including normal GB/SK workbook and Manifest generation;
- a rollback smoke using the complete v0.2.0-rc.1 package.

Verify the downloaded ZIP against its `.zip.sha256` companion before
extraction, then verify packaged files against `SHA256SUMS`.

## Known limitations

- Power loss or forced process termination can leave diagnostic
  `.costing-publish-*` or `.costing-tmp-*` files. A partial workbook is not
  published to the final output path.
- Bit-for-bit identical ZIP archives across rebuilds are not guaranteed;
  source identity, exact inputs, deterministic build metadata, checksums, and
  behavior are verified instead.
- `doctor`, human-readable logging, private scheduled runners,
  float-to-Decimal fast paths, Thin LTO, string interning, and Python
  retirement remain post-v0.2.0 work.

## Rollback

Keep each ZIP together with its external checksum. Roll back by deploying the
entire previous verified package; do not mix executables, configuration,
schemas, examples, or checksums from different versions.
