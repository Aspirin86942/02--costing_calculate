**Linux x86-64 构建已生成，真实完整 SK 验收失败。当前包仅供复验，请继续使用上一份已验证的同平台程序进行生产核算。** 本次构建来自提交 `1f6ae90d41e9b406f9e690fd94721ecfa4a4e33f`。

0.3.1 默认启用五项性能改动，沿用现有 GB/SK 命令、金额计算、三张结果表及 V1 审计格式。

- 大型单表 XLSX 按完整行并行读取并按原顺序合并，特殊布局交给原读取路径。
- 写出时共享已有文本，低内存模式在填充工作表的同时压缩行数据。
- 命令行使用 `mimalloc` 分配内存，退出时由系统回收展示表。可重复调用的 Rust 接口仍在每次调用后释放内存。

## Linux 构建与验收

0.3.1 正式源码通过 Rust 格式与静态检查、222 项 Rust 测试和 487 项 Python 测试。Linux 环境跳过一项 Windows 专用检查。受控 Excel 写出库的 83 个文件与登记哈希一致。

从干净提交构建一次，再将同一提交导出到独立目录，关闭编译缓存重新构建一次。两份可执行文件逐字节一致，SHA-256 为 `3bd08cedb513bcae2a4fcf29c540fae560612fcf5fc36f30e104898e1e74ce2d`。解压后的程序在子进程找不到 Rust 和 Python 的环境中通过了版本、配置及 GB/SK 合成运行检查。
