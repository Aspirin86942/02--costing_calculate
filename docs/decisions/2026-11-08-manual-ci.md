# GitHub CI 改为手动运行

- 状态：Accepted
- 日期：2026-11-08
- 范围：`.github/workflows/ci.yml`、`release.yml` 的发布前检查、`main` 分支保护

## 背景

`ci.yml` 自 2026-07-25 起，在每次推送到 `main` 和每个 PR 上自动运行 Windows / Ubuntu 公共门禁；`release.yml` 在打包前复用它。仓库只有一位维护者，近期 GitHub 运行记录均来自直接推送 `main`。

2026-11-08 推送 `60503d1` 后，Ubuntu 通过，Windows 因 4 项 Colab notebook 测试的平台差异失败。维护者认为自动 CI 没有必要，要求取消。

## 决策

1. `ci.yml` 删除 `push` 和 `pull_request` 触发，只保留 `workflow_dispatch`（在 Actions 页面手动运行）和 `workflow_call`（被其他 workflow 复用）。
2. 保留 `ci.yml` 文件：`release.yml` 的 `quality` 任务通过 `uses: ./.github/workflows/ci.yml` 复用它，发布前仍执行同一组门禁。
3. 删除只在 PR 事件运行的冻结基线策略步骤；`tools/ci/baseline_policy.py`、CODEOWNERS 和对应单元测试保留。
4. 提交前以 `AGENTS.md` 中的本地验证命令为准；需要云端 Windows 结果时，在 Actions 页面手动运行 CI。

## 影响

- 推送和 PR 不再触发 CI，也不再产生失败提示。
- Windows 上的回归不再被自动发现。涉及 Windows 的改动应在 Windows 本机或手动运行的 CI 中验证。
- `main` 分支保护仍要求 `Public gates (windows-latest)` 和 `Public gates (ubuntu-latest)`。保护规则没有对管理员强制，管理员直接推送不受影响；通过 PR 合并会因这两项检查不再产生而被阻止，需先在 GitHub 设置中移除必需检查。本决策没有修改该远端设置。
- PR 标签和说明检查（冻结基线策略）停止执行。

## 未选择的方案

- 删除 `ci.yml`：`release.yml` 会因找不到被复用的 workflow 而失败，发布前的质量检查也随之消失。
- 在 GitHub 页面禁用 workflow：该状态不在仓库内，文件、测试和文档仍会声明 CI 自动运行。
- 保持自动运行，只修复 Windows 测试：与维护者的决定不符。

## 恢复

在 `ci.yml` 的 `on:` 中恢复 `main` 的 `push` 和 `pull_request` 触发，以及 PR 专用的冻结基线策略步骤，并同步 `tests/architecture/test_ci_contract.py`。
