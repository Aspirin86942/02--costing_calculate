# SK 材料金额采用 ERP 汇总

- 状态：Accepted。
- 日期：2026-11-09。
- 授权：用户在材料金额口径选择中明确选择“ERP 汇总金额”。
- 当前契约：[工作簿与运行契约](../contracts/workbook.md)。
- 验收证据：[完整 SK 适配记录](../changes/2026-11-09-full-sk-erp-format.md)。

## 背景

完整 SK ERP 导出同时包含直接材料汇总行和材料子项明细。独立 XML 审计确认，12,969 张有效工单的材料子项合计与 ERP 汇总不同；这些差额与原程序的总成本勾稽差额完全一致。采用 ERP 材料汇总时，各成本项目与工单总完工成本能全部勾稽。

## 决策

SK 数量页和分析页使用 ERP 直接材料汇总金额计算材料金额、单位成本和异常分析。汇总按月份、产品编码、工单编号、工单行号归属，多条同键汇总累加。总表保留材料子项的原始金额。

汇总金额与子项合计不同，记录 `MATERIAL_DETAIL_MISMATCH`，并在数量页和分析页展示复核原因。汇总行存在但任一金额缺失或无法解析，该工单材料金额按 0 计算，记录 `MISSING_AMOUNT` 并标记需复核。缺少材料汇总行的精简输入沿用材料子项合计；GB 沿用既有明细口径。

## 影响与取舍

ERP 汇总为工单成本提供一致的计算依据，子项差异继续作为可核查的数据问题保留。总成本勾稽通过与整体数据校验状态分别表达：材料子项存在差异时，数量页仍显示“需复核”。

此前按材料子项合计计算的方式保留为无 ERP 汇总行时的规则。用户已选择在完整 SK 导出中采用 ERP 汇总，因而本次有依据地改变 SK 工单材料金额及相关分析结果；应用和 Manifest schema 版本维持现状。
