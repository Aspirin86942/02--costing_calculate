# 成本总表采用隐式坐标，保留显式格式

Windows 源码构建采用此方案。三份真实输入各 8 对均胜出并通过独立 N=5 的耗时、峰值工作集及文件大小门禁。完整 SK 的输出由 75,372,863 字节降至 32,003,666 字节。Linux 部署继续单独验收。[实测与 Excel 回存](../changes/2026-11-20-windows-workbook-export.md)

在每行中，连续数值、日期及共享文本的位置可由前一单元格推导。保留行号、跨空列的地址以及显式单元格样式。普通写出和低内存写出共用这一规则。以可覆盖的工作表选项控制，项目只在成本计算单总表开启。提高压缩等级曾在固定 XML 上测试，完整 SK 仍超过大小上限。省略显式金额样式会使 Excel 将部分金额显示为 `General`。[前期实验](../changes/2026-11-20-windows-stage-profile.md)

后台压缩的低内存工作表使用已完成的 ZIP 本地头，保存时将单成员包整体并入最终流。坐标优化可以单独撤回，Excel 封装及格式尾行修复应保留。Linux 段错误已有发生在读取和计算阶段的记录，共用写出代码的正确性修复不能作为 Linux 内存或崩溃验收的依据。[Linux 版本记录](../changes/releases/v0.3.1.md)

Windows x64 提供可选 PGO 构建。用三份合成输入训练，独立为两阶段构建分配目录并保留二进制和 profile 身份。PGO 适用于看重耗时的日常写出。完整 SK 审计时常规构建的峰值工作集中位数约低 56 MiB，保留常规构建供内存敏感环境使用。Linux 需要在自身平台重新训练、测量和核对。[构建方法](../performance/README.md#windows-pgo-候选构建)
