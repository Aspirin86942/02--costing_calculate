# v0.2.0 M3 Configuration Governance — 2026-07-25

## Scope and decision

M3 replaces the Rust production path's static product-order arrays with a
versioned, fail-closed `FileConfigV1`. The CLI application layer owns parsing,
validation, source precedence and hashing; `costing-core` receives only an
owned, validated `PipelineRules`.

The repository owner approved the reviewed production dependencies on
2026-07-25. The exact versions, licenses, checksums, maintenance status and
lockfile delta are recorded in
`docs/dependencies/2026-07-25-toml-sha2-review.md`.

with zero mismatches:

- M0 baseline versus M3 embedded;

The repository's `workbook_compare` oracle checked Sheet order, package
relationships, shapes, panes, filters, widths, number formats, styles,
conditional formats, every cell value and business reconciliation. Raw XLSX
SHA-256 values differ because each run writes a different document metadata
timestamp; this is not a business or workbook-contract difference.

and runtime counts. GB reported `MISSING_AMOUNT=17,193` and
`NON_POSITIVE_UNIT_COST=3,322`; SK reported `MISSING_AMOUNT=168,424` and
`NON_POSITIVE_UNIT_COST=33,391`.

## Failure and boundary proofs

- `--validate-config` and `--print-effective-config` complete without opening
  a workbook.
- Unknown fields, missing pipelines, invalid UTF-8, invalid TOML types,
  duplicate product identities/orders and unsafe input patterns fail before
  input discovery.
- GB and SK standalone cost items accept only their exact frozen sets and
  order.
- External whitespace, comments and key ordering do not change the effective
  semantic hash.
- `costing-core` contains no TOML parser, filesystem/config-path read,
  environment read or CLI argument dependency.
- The synthetic embedded/external workbook test is byte-identical; the real
  three-way oracle proof above is semantically identical.
