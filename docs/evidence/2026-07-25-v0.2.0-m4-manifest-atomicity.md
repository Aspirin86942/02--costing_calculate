# v0.2.0 M4 Manifest and Atomic Publication — 2026-07-25

## Scope and reviewed commits

M4 adds the optional, versioned `RunManifestV1` audit record and changes both
workbook and Manifest publication to a same-directory staging file followed by
flush, file sync, and no-overwrite publication.

The implementation and review-remediation commits are:

- `27022eecef7e63e81d03c891edf3381e351c255a`
- `ee0530dc658c8eda0fc1cb198eb77668532d1a84`

No production package was added for M4. `tempfile`, `chrono`, `calamine` and
`sha2` were already reviewed workspace dependencies.

## Manifest contract

- Without `--summary-output`, the existing `RunSummary`/error JSON and exit-code
  paths remain unchanged and no file SHA-256 is calculated.
- With `--summary-output`, the input is read once. Calamine parses the same
  immutable byte snapshot used for `input.sha256`; a concurrent path
  replacement cannot change the evidence after ingest.
- A normal run hashes only the final published workbook. A check-only run writes
  only the Manifest with `output_written=false`.
- Success and failure variants use a closed serde model, reject unknown fields,
  reject status values outside the v1 vocabulary, and reject
  `schema_version != 1`.
- The published JSON schema is closed and its error-code/stage vocabulary is
  compared directly with the runtime enums. Golden success/failure documents
  round-trip through the typed model.
- `--redact-paths` makes paths below the current directory relative and reduces
  external paths to their basename while retaining hashes.
- Failure manifests contain no business detail rows.

## Atomicity and failure-injection matrix

| Scenario | Standard writer | Low-memory writer | Result |
| --- | --- | --- | --- |
| Final workbook already exists | Covered | Shared preflight | Fails before workbook ingest; original bytes unchanged |
| Final summary already exists | Shared preflight | Shared preflight | Fails before damaged workbook ingest; original hash unchanged |
| Staging workbook write fails | Covered | Covered | No final workbook; staging and low-memory workspace cleaned |
| Workbook publication race | Covered | Covered | Competitor bytes preserved; no false success |
| Catchable `Interrupted` I/O | Covered | Covered | Stable writer stage, retryable source, no final workbook or temporary artifact |
| Failure after workbook publication | Covered | Covered | Workbook opens; writer mode and `final_output_valid=true` retained |
| Output metadata failure after publication | Covered | Covered | Published workbook retained; failure Manifest recovers size and SHA-256 |
| Manifest staging write fails | Shared publisher | Shared publisher | No final Manifest or staging artifact |
| Manifest publication race | Shared publisher | Shared publisher | Competitor Manifest preserved |
| Manifest fails after workbook success | Covered | Mode propagated independently | Non-zero outcome; workbook retained, opens, and has path/hash evidence |
| Flush versus sync failure | Covered | Covered | Distinct stable workbook and summary stages |

`AtomicFile` and the low-memory `TempWorkspace` are RAII-owned, so recoverable
errors and unwinding attempt cleanup. As allowed by the PRD, power loss or
forced process termination may leave a diagnostic `.costing-publish-*` or
`.costing-tmp-*` file; the final path is still never a partial workbook.
Automatic stale-file deletion and `doctor` remain post-v0.2.0 work.

## Independent review resolution

### Standards review

The standards review found three hard issues and one judgment issue.

- The Windows-only path assertion now constructs the expected native path and
  is portable to Ubuntu CI.
- Workbook and Manifest flush failures no longer collapse into write/sync
  stages.
- Current-directory lookup is explicit and fail-closed; no `"."` fallback
  remains.
- The Manifest module remains cohesive around one private application concern.
  Its public DTOs now have API documentation; splitting it further was not
  required for correctness and would add churn inside M4.

### Specification review

The specification review found five behavioral gaps.

- Post-publication writer errors now propagate actual writer mode and valid
  output state into stderr and the failure Manifest.
- Published-output identity is recovered after metadata or low-memory cleanup
  failure without replacing the primary writer error.
- Input hash and parser consume the same captured bytes.
- Catchable interruption is injected for both writer modes and proves
  best-effort cleanup without panic abort.
- Future manifest schema versions are rejected during deserialization.

No separate JSON-schema-engine dependency was added. The approved M4 contract
uses the closed typed model, golden round-trip tests, future-version rejection,
and direct schema/runtime vocabulary checks required by the PRD.
