# v0.3.0 全项目整理计划

- 状态：Completed
- 日期：2026-07-27
- 目标版本：v0.3.0
- 基线标签：`cleanup-baseline-2026-07-27`

## 目标

- Rust 成为唯一正式业务实现。
- Python 只保留工作簿比较、合成测试数据和发布验收工具。
- 正式 Rust CLI、工作簿、错误模型和 `RunManifestV1` 保持兼容。
- 退役 `uv run python main.py gb/sk`，并将 workspace 版本升级到 `0.3.0`。
- 删除退役实现和迁移脚手架，不新增业务功能或生产依赖。
- 保持 `docs/superpowers/` 只读。

## 实施顺序

1. 冻结基线：通过现有门禁，创建恢复标签，保存忽略目录中的基线 binary，并记录脱敏验收数据。
2. 收敛 Rust：保留四个 crate，以小型内存处理接口隐藏 normalize、split、fact、anomaly 和 presentation 实现。
3. 精简 Python：先提取验证工具，再删除 Python 业务实现、Phase 0/meta 脚手架和已退役 GUI。
4. 同步事实：更新 README、AGENTS、架构/契约文档、依赖、CI、发布流程和版本。
5. RC 验收：完成真实 GB/SK、合成数据、性能、Windows 包和无开发环境 smoke，准备 `v0.3.0-rc.1`。

## 兼容边界

除版本字段、发布标签和 Python 旧入口退役外，以下行为不得变化：

- Rust CLI 命令、参数、默认路径、禁止覆盖和 check-only 语义；
- 成功/失败 JSON、错误码和 `retryable`；
- 三张 Sheet 的名称、顺序、字段、数值、样式和业务勾稽；
- GB/SK 独立成本项、白名单顺序、异常阈值和 Decimal 语义；
- Manifest V1、路径脱敏、SHA-256、原子发布和 low-memory 行为。

## 验收

- Rust fmt、Clippy、全 workspace/全 feature 测试和架构测试通过。
- 精简后的 Python Ruff、pytest、合成 GB/SK 和发布 smoke 通过。
- 基线与候选 workbook 按现有 OOXML 比较规则等价；数值容差保持单元格 `1e-9`、列累计 `1e-8`。
- GB/SK 真实数据 full 和 check-only 通过，且不提交敏感输入、输出或本地路径。
- 不突破当前性能和内存硬门禁；任何优化必须有配对实验。
- 没有 `main.py`、`src/`、`tests.rust_oracle` 或旧 Python CLI 的活动引用。
- Markdown 链接、旧路径、`git diff --check`、UTF-8/EOL 和最终工作区检查通过。

## 回滚边界

- 每个阶段独立提交并独立通过门禁。
- 删除前必须先提取并验证替代能力。
- 任一阶段失败只回退该阶段，不使用 `reset --hard`。
- 退役代码可从 `cleanup-baseline-2026-07-27` 恢复。
- 推送发布标签和发布外部资产前必须再次确认。
