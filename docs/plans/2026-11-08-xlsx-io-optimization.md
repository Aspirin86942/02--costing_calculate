## 目标与不变条件

降低普通电脑的完整处理时间。先定位真实热点，再比较有限候选；主场景端到端改善至少 5%，至少胜出 6/8 对。没有候选通过则保留原程序。

Rust `1.96.0`、release、`codegen-units = 1`、通用 x86_64、唯一 Rust 业务实现保持不变。三张 Sheet 的顺序、字段、类型、样式、金额语义及业务规则不变；单元格容差 `1e-9`、列累计 `1e-8`。低内存切换保持单张 Sheet 数据行数 × 列数达到 `5,000,000`；临时文件位于输出目录，保留 flush/sync、禁止覆盖、原子发布、错误及清理语义。

保留 reader 安全整数快路径、`Arc<str>`、列行为预计算和空白跳过。没有新证据不重试已拒绝的缓冲、LTO、`zmij`、降压缩等级及文本驻留池。

## 已确认的设计边界

- `ingest` 在有 Manifest 时包含读文件和输入哈希，输出哈希在 `export` 外；`export` 还包含准备、发布、销毁和清理，阶段不能直接相加为端到端。
- 普通工作簿使用当前后端默认压缩等级 6，低内存工作簿显式设为 5；迁移时保持实际行为并修正事实文档。
- 当前 `rust_xlsxwriter` fork 已按 Sheet 并行生成 XML，随后顺序压缩 ZIP。低内存模式在填表时写行 XML；共享字符串首次分配顺序必须确定。
- 上游 0.102.0 需要适配工厂 `Result`、新临时文件错误和压缩 API；仍需移植本地写/flush/rewind/copy 的错误传播补丁。作者对 C 版的 1.6 倍比较不是本项目收益。
- calamine 已有借用 Range，XLS/ODS 通用借用接口有未实现分支，优化必须限定支持路径，保留首表、空洞、双表头、文本和 Decimal 行为。

## 诊断与工具复用

复用 `measure_paired_release.py`、`compare_releases.py`、`workbook_compare.py`、`synthetic_benchmark.py`、`autotune_experiment.py`、`prepare_colab_bundle.py` 和 Windows 原测量脚本。

隔离诊断版本按较大的区间计时：读取/输入哈希/公共元数据/工作表解析/单元格转换，工作表填充/SST/XML/各 ZIP 条目/ZIP 收尾，flush/sync/发布/销毁/清理/输出哈希/Manifest 发布。不逐单元格读取时钟，不改公开阶段和 Manifest。

现有 `strace -f -c -w` 仅统计调用与停留时间，不能直接解释为物理磁盘等待。CPU 采样采用仅在诊断快照加入的 pprof `0.15.0`，保持稳定 Rust，不改内核或装全局工具；记录样本质量，超时/崩溃/丢样明确标无效。带诊断的结果不进入正式排名。

固定 XML 语料和已读入内存的 XLSX 分别做压缩、解析与写出隔离实验，记录哈希、大小、压缩比及类型分布。诊断依赖和补丁不进入默认生产构建。

P2 必须保留原源码/profile 保护，依赖候选仅允许声明的 TOML 键、锁文件包身份和源码载荷，禁止无目标的整体 `cargo update`；载荷按逐文件哈希、来源、许可证及安全目标路径复制。实际执行工具与冻结清单核对；诊断、筛选、验收和有/无 Manifest 的批次明确分开。工具变化后不混用旧计时。

同时核验 `sheets/per_month`、分析页非空及实际阈值；大样本至少一次进入非字节相同的完整语义比较。比较过程也有资源上限，不能改成抽样。父子阶段目标范围开测前冻结，避免重复归因或事后扩大豁免。

大型语义场景预登记为 `gb-large-semantic`：above-threshold 输入、2025-12 至 2026-01，保留超过 100,000 条正常明细。合成脏工单集中在三月；另用正常月份避免严格比较器把故意脏数据判为非法。三张 Sheet 全部比较，原全月脏数据、实际阈值上下两侧与质量计数检查继续保留。

## 场景和固定门槛

初筛为 GB 中型合成、normal+Manifest、种子 `20261108`。保护集覆盖 GB/SK 小型/中型/阈值两侧、种子 `20261109`、normal/check-only、单月/跨月/空月、内嵌与外部配置、文本/数量/异常边界。等于阈值与溢出用单元测试。C6/组合额外比较单核与两核；双方 CPU 集合相同。

无 Manifest normal 实际省略 `--summary-output`，校验在计时外完成，不能从已有耗时减去哈希来推断。真实目标机日常无 Manifest normal 为最终主场景，有审计模式也单独验证。

| 项目 | 门槛 |
|---|---|
| 校准 | 同基线 4 对；配对差中位数绝对值 <1%，逐对绝对差中位数 ≤2%，目标阶段 <5%；最多两次 |
| 主场景 | 8 对交错，先算每对 `(B−C)/B` 再取中位数；至少 +5%，至少 6/8 胜出 |
| 其他场景 | 回退 ≤2%；目标范围外 ≥50ms 阶段回退 >5% 拒绝 |
| 内存 | 逐对改善中位数 ≥−5%，且候选峰值中位数/基线 ≤1.05；CLI 每次 ≤2 GiB |
| 输出 | 合成最大值 ≤基线 102%；固定真实样本守原绝对上限 |
| 组合 | 原基线 ≥+5%；相对最佳单项额外 ≥+2% 且 ≥6/8；其他约束相同 |
| 最终复测 | 独立 N=5，每侧五次；主场景 ≥+5%、≥4/5，不能并入前 8 对 |

Linux RSS 与 Windows PWS 分开。Windows 固定样本原门槛：GB `3.2554s / 375,700,685 bytes / 4,194,321 bytes`；SK `20s / 2,147,483,648 bytes / 48,658,823 bytes`。原运行方式保留，不跨平台或跨输入套用。

## 验证、预算与交付边界

候选先跑受影响测试；最终运行 AGENTS 中 Rust fmt/clippy/test、Python Ruff/pytest、Markdown 链接、release 构建和合成端到端。新增边界测试覆盖未知字段、恢复身份、路径/依赖越界、错误锁文件、诊断混入排名、组合参考错误和资源失败。新库移植必须覆盖故障注入、原 OS 错误、清理与发布后文件有效性。完整工作簿比较不放宽。

每个正式批次含构建/正确性/计时最多 6 小时，CLI 最多 600 秒、2 GiB 内存及 2 GiB 运行目录。连续三次同路径没有新证据则停止；不挑最好一次，不自动增预算。正式程序从原业务基线和已采纳补丁重新构建，不能交付带诊断代码的实验程序。

当前真实 SK 和 Windows/Excel/WPS 环境缺失，不能完成全部 P6/P7。可独立完成已就绪的 Linux 诊断、工具和筛选；缺项明确标“未验证”，不以合成或跳过代替通过。自动 CI 保持关闭。

真实输入输出、XML 与原始日志留在忽略目录。依赖/fork 源码、默认配置及业务标识也需要审阅后才能上传。最终源码、工具、实验与拒绝原因、二进制身份及旧程序回退材料一并保存。
